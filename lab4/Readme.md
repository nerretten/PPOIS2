
# Лабораторная работа №4

Данный проект представляет собой интерактивную программную модель, имитирующую деятельность палеонтологического исследовательского центра. Программа объединяет научные исследования, экономическое планирование и управление ресурсами.

## Архитектура приложения

Проект реализован с использованием **многослойной архитектуры**, что обеспечивает независимость бизнес-логики от способа отображения данных:

1. **Слой данных (`src/models.py`)**: Описывает структуру сущностей. Используются `dataclasses` для хранения состояния объектов.
2. **Слой бизнес-логики (`src/services.py`)**: Содержит сервисы, которые инкапсулируют правила игры (расчеты шансов, стоимости, логику переходов состояний).
3. **Интерфейсный слой**:
* **CLI (`src/cli_app.py`)**: Консольное приложение для управления через текстовые команды.
* **Web (`src/web_app.py`)**: Веб-интерфейс на базе FastAPI с использованием шаблонов Jinja2.


4. **Слой сохранения (`PersistenceService`)**: Обеспечивает сериализацию данных в JSON-файл, позволяя сохранять и загружать игровой процесс.

##  Игровые механики и процессы

### 1. Полевые экспедиции (Раскопки)

Игрок выбирает одну из трех геологических формаций (Моррисон, Зольнхофен, Тяоцзишань), каждая из которых имеет свой уровень сложности.

* **Стоимость**: Каждая попытка раскопок стоит **10 единиц энергии** исследователя.
* **Вероятность успеха**: Шанс найти ископаемое (`success_chance`) динамически рассчитывается на основе базового шанса (60%), бонуса за навык исследователя и штрафа за сложность породы.
* **Целостность**: В сложных породах ископаемое может получить повреждения при извлечении, что снижает его целостность (`integrity`).

### 2. Лабораторный анализ

Найденные образцы поступают в инвентарь в статусе «Выкопано» (`EXCAVATED`).

* **Процесс**: Исследование стоит **5 единиц энергии**.
* **Результат**: Образец переходит в статус «Изучено» (`ANALYZED`). Увеличивается общий уровень знаний о Юрском периоде и повышается навык исследователя.
* **Климат**: По мере роста уровня знаний (при достижении 30% и 70%) игроку открывается подробная информация о климате изучаемого периода.

### 3. Музей и Экономика

Цель этого этапа — монетизация находок для финансирования дальнейших раскопок.

* **Создание макетов**: Стоит **300 монет**. На основе изученных костей создаются экспонаты. Качество макета зависит от целостности костей и текущей научной точности (уровня знаний).
* **Выставки**: Приносят доход в бюджет музея и повышают его репутацию. Доход зависит от общего качества представленных в зале экспонатов и случайного бонуса (посещаемости).

### 4. Управление ресурсами

* **Энергия**: Ограниченный ресурс исследователя. Если энергия заканчивается, действия блокируются.
* **Отдых**: Команда «Отдохнуть» полностью восстанавливает энергию до 100%.

## Технические особенности

* **Конфигурация**: Все балансовые константы (шансы, множители, стоимости) вынесены в класс `GameConfig`, что позволяет легко изменять правила игры без правки кода логики.
* **Состояния ископаемых**: Реализован жизненный цикл объекта через `Enum`: `BURIED` (в земле) → `EXCAVATED` (выкопано) → `ANALYZED` (изучено) → `DISPLAYED` (выставлено).
* **Обработка ошибок**: Использование кастомных исключений (`ResourceError`, `WorkflowError`) позволяет корректно уведомлять пользователя о нехватке ресурсов или нарушении логики действий (например, попытка изучить еще не выкопанную кость).
* **Веб-интерфейс**: Реализован на FastAPI с применением паттерна PRG (Post-Redirect-Get) для предотвращения дублирования действий при обновлении страницы. Данные между страницами передаются через URL-кодированные сообщения (`urllib.parse.quote`).
